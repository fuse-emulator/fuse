* Start fuse as ./fuse --beta128 --betadisk lib/tests/success.udi
* At the A> prompt, enter LOAD "success"
* You should see "Congraturation! You sucsess!"

* Start fuse as
  ./fuse --plusd --plusddisk lib/tests/success.mgt PlusDSystemTape.tzx

* Hit <Break>

DivIDE

* Acquire the FATware installer from
  http://web.archive.org/web/20150302052256/http://baze.au.com/divide/
* Uncompress lib/tests/fatware-success.hdf.bz2
* Start fuse as
  ./fuse --divide --divide-masterfile fatware-success.hdf FATware-0-12.tap
* Follow prompts; the "JP2 (E) jumper" is the DivIDE write protect option.
* When rebooting, you should see "0 Created by hdfmonkey  LBA"
* Fire an NMI; you should see a file selector with "SUCCESS.TAP" highlighted
* Press Enter and then LOAD ""
* You should see "Program: success",
  followed by "Congraturation! You sucsess!"

JLO Disk System

* Obtain the external 8 KiB SAFE 2.65 ROM and read its copyright notice:
  https://www.timexsinclair.com/computer_media/jlo-safe-dos-v2-65/index.html
  SAFE is copyrighted freeware and is not distributed with Fuse.
* Start fuse as
  ./fuse --machine ts2068 --jlo --rom-jlo /path/to/safe265.rom --jlo0disk-new
  Use --machine 2068 for a TC2068. Other machine models do not enable JLO.
* Only on the new blank disk, enter FORMAT /"TEST", then CAT.
* Enter a BASIC program, for example 10 PRINT "JLO".
* Enter SAVE /"TEST", then CAT and check that TEST is listed.
* Enter NEW, then LOAD /"TEST" and RUN. The program should print "JLO".
* Use Media, Disk, JLO, Drive 0:, Save As... to save the image (for example
  as .udi). Eject and reinsert that image, then repeat LOAD and RUN to
  check that the image survives a save/reopen round trip.
* Restart with that .udi image as a positional argument instead of
  --jlo0disk-new, and also try File, Open... while JLO is enabled. Both
  should insert it into JLO drive 0 without changing the Timex model.
* With a CPCEMU .dsk image, File, Open... and positional startup should
  instead select the +3. To keep the Timex/JLO setup, use Media, Disk,
  JLO, Drive 0:, Insert... or the explicit --jlo0disk option.
* With an automation-enabled build, an existing output directory and
  --no-auto-load --automation-output /path/to/output --automation-frames 1,
  check result.json: identity.disk must give the input size and CRC-32
  before disk-format normalisation (after decompression, if applicable).
  For the positional .udi image, identity.disk_location must name
  controller "jlo" and drive 0; for positional CPCEMU .dsk, "plus3" and
  drive 0. Repeat with explicit --jlo0disk through --jlo3disk, checking
  controller "jlo" and the corresponding zero-based drive number for
  either format.
